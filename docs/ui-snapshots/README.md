# UI snapshots

Automated screenshots for build-in-public / Confluence posts.

## Quick commands

```bash
# Current week only (prod) + refresh Confluence markdown — use this as you ship features
npm run capture:current-week

# All weeks from git history + refresh doc (~5 min)
npm run capture:and-sync

# Regenerate doc only (after manual PNG changes)
npm run sync:confluence-doc
```

## Capture options

```bash
npm run capture:snapshots -- --current
npm run capture:snapshots -- --milestones
npm run capture:snapshots -- --url https://ncaaf-data-collection.vercel.app --label week-4
npm run capture:snapshots -- --commit 1cbc5bb --label week-1
```

Each run writes PNGs under `docs/ui-snapshots/<label>/`:

- `fixtures-landscape.png` — iPhone 13 landscape (844×390 logical, @3x), `/fixtures`
- `game-landscape.png` — iPhone 13 landscape game view
- `features/*.png` — feature-specific states for that week (week 4 includes one portrait shot: `portrait-stack.png` at iPhone 13 390×844)
- `meta.json` — capture timestamp, URLs, and feature list

Game screenshots dismiss the field-direction dialog and error toast by default. Only the **`field-direction-dialog`** and **`error-toast`** feature shots intentionally show those overlays.

## Keeping the Confluence doc in sync

Snapshot **tables and image embeds** in `docs/confluence-weekly-build-in-public.md` are **auto-generated** between HTML comment markers:

| Marker | Content |
|--------|---------|
| `ui-evolution` | Latest fixtures + game console overview screens, landscape only (executive summary) |
| `week-N-interactions` | Feature screenshots inline with Core / Key interactions copy |
| `week-N-shipped-<key>` | Feature screenshots inline in Shipped subsections |

Edit interaction text in `WEEK_INTERACTIONS` and shipped image mappings in `WEEK_SHIPPED` (`scripts/ui-snapshot-doc-content.mjs`).

```markdown
<!-- AUTO-SNAPSHOTS:ui-evolution:START -->
... regenerated by npm run sync:confluence-doc ...
<!-- AUTO-SNAPSHOTS:ui-evolution:END -->
```

Your prose (Overview, Shipped, Technical notes) stays manual. Only the snapshot sections update.

### Adding a new feature mid-week

1. Add a scenario to `scripts/ui-snapshot-features.mjs` under the current week key.
2. Run `npm run capture:current-week`.
3. Commit the PNGs + updated markdown.

### Starting a new week (e.g. week-5)

1. Add `{ label: 'week-5', commit: 'HEAD', date: '2026-07-14' }` to `scripts/ui-snapshot-weeks.mjs`.
2. Add feature scenarios under `'week-5'` in `ui-snapshot-features.mjs`.
3. Add a `## Week 5` section to the Confluence doc (prose only), plus markers in Shipped subsections and in the interactions section:
   ```markdown
   <!-- AUTO-SNAPSHOTS:week-5-shipped-my-feature:START -->
   <!-- AUTO-SNAPSHOTS:week-5-shipped-my-feature:END -->

   <!-- AUTO-SNAPSHOTS:week-5-interactions:START -->
   <!-- AUTO-SNAPSHOTS:week-5-interactions:END -->
   ```
4. Run `npm run capture:current-week`.

## CI (GitHub Actions)

Workflow: `.github/workflows/ui-snapshots.yml`

- **On push to `main`** (when `src/` changes): captures production and uploads artifacts.
- **Manual → milestones**: full history capture + doc sync.
- **Manual → production**: prod capture + doc sync (dates/timestamps only if PNGs unchanged).

Download PNGs from the run’s **Artifacts** tab when not committing images to git.

## Publishing to Confluence

Images in the auto-generated sections use **GitHub raw URLs** (detected from `git remote origin` + current branch). Minimal workflow:

1. `npm run capture:current-week` (or `capture:and-sync` for all weeks)
2. **Commit and push** `docs/ui-snapshots/` and `docs/confluence-weekly-build-in-public.md` to `main`
3. Import or paste the markdown into Confluence — images load from GitHub (no manual uploads)

Example URL shape:

`https://raw.githubusercontent.com/GS-MarkBailey/NCAAF-Data-Collection/main/docs/ui-snapshots/week-4/game-landscape.png`

Image URLs include a `?v=` query param derived from each PNG’s file modification time, so markdown preview tools and Confluence refetch after re-capture. Re-run `npm run sync:confluence-doc` after updating PNGs.

Override the host with `CONFLUENCE_IMAGE_BASE_URL` if needed.

**Note:** Confluence must be allowed to fetch external images (usually on by default). Private repos require readers to have GitHub access; for org-wide Confluence, a **public** repo or GitHub attachment sync is more reliable.

## Feature scenarios per week

Overview captures are **landscape only** for every week. The only **portrait** screenshot is the `portrait-stack` feature in week 4.

| Week | Overview captures |
|------|-------------------|
| All | Landscape fixtures + game |

Week 4 also sets `portrait: true` in config to mark portrait iPhone layout shipping; portrait overview PNGs are not captured.
